# 04 — REST API v1 (mobile + portal)

The web app uses Inertia and does **not** go through this API. This API exists for the future mobile apps (customer, collector, technician) and any third-party integration. Build it in Phase 7, but read this file before Phase 2 so the models don't fight the contract.

## 1. Ground rules

- Base URL: `https://<host>/api/v1`
- Auth: `Authorization: Bearer <sanctum-token>`
- Content: `application/json` in and out; `multipart/form-data` for uploads only.
- **Never expose sequential IDs.** All resources are addressed by `uuid`.
- Required request headers: `Accept: application/json`, `X-Client: {app}/{version}`, `X-Device-Id: <uuid>`, `Accept-Language: en|ar|fr`.
- Documentation is generated by `dedoc/scramble` at `/docs/api` and exported as OpenAPI 3.1 to `storage/api/openapi.json` in CI. The generated spec is the contract handed to the mobile team.
- Versioning: additive changes only within `v1`. A breaking change means `v2` mounted alongside. Never change the meaning of an existing field.

### Response envelope

Single resource:
```json
{ "data": { ... }, "meta": { } }
```
Collection:
```json
{
  "data": [ ... ],
  "meta": { "next_cursor": "eyJpZCI6MTIzfQ", "prev_cursor": null, "per_page": 50 },
  "links": { "next": "https://.../api/v1/customers?cursor=..." }
}
```

Use **cursor pagination** everywhere. Offset pagination breaks under concurrent writes and is slow at depth, and field apps page through large lists.

### Errors — RFC 9457 problem details
```json
{
  "type": "https://api.example.com/problems/validation-failed",
  "title": "Validation failed",
  "status": 422,
  "detail": "The phone has already been taken.",
  "instance": "/api/v1/customers",
  "errors": { "phone": ["The phone has already been taken."] },
  "trace_id": "01J8XK..."
}
```
Codes used: `400` malformed, `401` unauthenticated, `403` unauthorised/insufficient ability, `404` not found or not in your tenant (**return 404, not 403, for cross-tenant access — do not leak existence**), `409` conflict (idempotency mismatch, stale version), `422` validation, `423` locked (e.g. shift closed), `429` rate limited (with `Retry-After`), `503` upstream/device unavailable.

### Idempotency
Any `POST` that creates money, a network command, or a work-order completion **must** send `Idempotency-Key: <uuid>`. The server stores the response for 24h. A repeat with the same key returns the original response and `Idempotency-Replayed: true`. A repeat with the same key but a *different* body returns `409`.

### Concurrency
Mutating a resource sends `If-Match: <etag>` where the client has one. Server returns `409` on mismatch with the current representation in the body so the client can merge.

## 2. Authentication

| Method | Path | Notes |
|---|---|---|
| POST | `/auth/staff/login` | `{email, password, device_name, device_id}` → token + user + abilities. `422` if 2FA required → `{two_factor_required: true, challenge_id}` |
| POST | `/auth/staff/two-factor` | `{challenge_id, code}` → token |
| POST | `/auth/customer/otp/request` | `{phone}` → `{expires_in, resend_after}`. Rate limited. **Always returns 200** whether or not the phone exists — do not confirm subscriber existence to an unauthenticated caller. |
| POST | `/auth/customer/otp/verify` | `{phone, code, device_id}` → token |
| POST | `/auth/logout` | revokes current token |
| GET | `/auth/me` | current identity, abilities, tenant branding, feature flags |
| POST | `/auth/devices/{uuid}/revoke` | logged-in device management |
| POST | `/auth/push-token` | `{token, platform, app}` |

**Token abilities:** `customer`, `staff:collector`, `staff:technician`, `staff:operator`, `staff:manager`. A token carries exactly the abilities its role permits; abilities are checked with `tokenCan()` **in addition to** the policy check, not instead of it.

### `POST /collector/payments`
```json
{
  "customer_uuid": "…",
  "amount": 500000,
  "currency": "LBP",
  "fx_rate": 89500.0,
  "fx_override_reason": "street rate",
  "method": "cash",
  "allocations": [{ "service_uuid": "…", "amount": 500000 }],
  "received_at": "2026-08-10T14:05:00+03:00",
  "device_recorded_at": "2026-08-10T14:03:12+03:00",
  "note": "collected at door",
  "latitude": 33.83, "longitude": 35.54
}
```
Headers: `Idempotency-Key` required.

Response `201`:
```json
{
  "data": {
    "uuid": "…", "receipt_number": "RCP-2026-000431",
    "amount": 500000, "currency": "LBP",
    "base_amount": 559, "base_currency": "USD",
    "customer": { "uuid": "…", "name": "…", "balance_after": 0 },
    "services_extended": [{ "uuid": "…", "expires_at": "2026-09-10T00:00:00+03:00" }],
    "reactivation": { "status": "queued", "command_uuid": "…" },
    "receipt_url": "https://…"
  }
}
```

Notes:
- If `fx_rate` is omitted the server uses the current tenant rate. If supplied and it differs from the current rate, `fx_override_reason` is required and the payment is flagged for review.
- `allocations` may be omitted; the server then applies oldest-invoice-first, or renews the single active service in prepaid mode.
- The response tells the client **what happened to the service and to the network**, so the collector can say "you're back on" with confidence rather than guessing.

### Offline sync
| Method | Path | Notes |
|---|---|---|
| GET | `/collector/sync/bootstrap` | `?zone=` full snapshot the device caches: customers in scope, balances, plans, current FX rates, message templates. Returns `sync_token`. |
| GET | `/collector/sync/delta` | `?since=<sync_token>` changes only: upserts + tombstones. |
| POST | `/collector/sync/push` | array of queued payments, each with its own `idempotency_key`. Returns per-item result (`created`, `replayed`, `rejected` + reason). **Partial success is normal** — never fail the whole batch because one item is bad. |

Max batch 100 items. Server processes each in its own transaction.

## 6. Shared / operator endpoints (ability: `staff:operator` and above)

Standard REST for `customers`, `services`, `plans`, `invoices`, `payments`, `tickets`, `work-orders`, `routers`, `zones`. All support `spatie/laravel-query-builder` conventions:

```
GET /api/v1/customers
  ?filter[status]=active
  &filter[zone]=<uuid>
  &filter[search]=70123
  &filter[expires_before]=2026-08-15
  &sort=-created_at
  &include=services,zone
  &cursor=…
```

Whitelist filters, sorts, and includes explicitly. Never allow an arbitrary column filter — it's an injection and an index-miss vector.

Service state actions:
| Method | Path | Notes |
|---|---|---|
| POST | `/services/{uuid}/activate` | |
| POST | `/services/{uuid}/suspend` | `{reason, note}` |
| POST | `/services/{uuid}/resume` | fails with `409` if suspension reason is not `auto_overdue` and the caller lacks `services.force_resume` |
| POST | `/services/{uuid}/pause` | `{reason, resume_at?}` — preserves days per tenant policy |
| POST | `/services/{uuid}/change-plan` | `{plan_uuid, effective: immediate\|next_cycle}`; `POST /services/{uuid}/plan-change-previews` returns the proration first |
| POST | `/services/{uuid}/renewal-previews` | returns a signed short-lived preview (`preview_id`, totals, new expiry) |
| POST | `/services/{uuid}/renewals` | `{preview_id, periods}` + `Idempotency-Key` |
| POST | `/services/{uuid}/terminate` | `{reason}`; preserves history, triggers equipment recovery workflow |
| POST | `/services/{uuid}/disconnect-session` | |
| POST | `/services/{uuid}/resync` | re-push desired state to the device |
| GET | `/services/{uuid}/network-commands` | recent command history + errors |
| POST | `/provisioning-commands/{uuid}/retries` | manual retry from the attention queue |

All of these return `202 Accepted` with a `command_uuid` when the effect is asynchronous, plus the new **commercial** status immediately (the **provisioning** status resolves via poll/websocket). Clients poll `GET /network-commands/{uuid}` or subscribe to the websocket channel.

## 7. Realtime

Laravel Reverb (or Pusher) channels:
- `private-tenant.{tenantUuid}.services.{serviceUuid}` — status and `network_state` changes
- `private-tenant.{tenantUuid}.tickets.{ticketUuid}` — new messages
- `private-tenant.{tenantUuid}.noc` — router up/down, incidents
- `private-customer.{customerUuid}` — payment posted, service reactivated

Authorisation via `/broadcasting/auth` with the Sanctum token. Every channel authorises tenant membership explicitly.

Push notifications (FCM/APNs) mirror the important ones for when the app is closed: payment received, service suspended, service reactivated, work order assigned, ticket replied.

## 8. Webhooks (outbound, Phase 9)

Tenants can register endpoints for `payment.recorded`, `service.suspended`, `service.activated`, `invoice.issued`, `ticket.created`, `incident.opened`. Signed with HMAC-SHA256 over the raw body in `X-Signature`, timestamped in `X-Timestamp` (reject > 5 min skew), retried 5 times with backoff, with a delivery log in the UI.

Inbound gateway webhooks (`POST /api/v1/webhooks/gateways/{gateway}`) verify the provider signature, are idempotent on the provider's event ID, and post through the **same** `RecordPayment` action as a cash payment. One code path for money, always.

## 9. Rate limits

| Scope | Limit |
|---|---|
| Unauthenticated (login, OTP request) | 5/min per IP, 3 OTP per 15 min per phone |
| Authenticated, per token | 60/min |
| Per tenant, all tokens | 600/min |
| Payment creation, per token | 20/min |
| Sync push | 6/min |
| Session restart (customer) | 1/5min per service |

Return `429` with `Retry-After` and `X-RateLimit-*` headers.

## 10. Mobile-specific concerns to design for now

1. **Bandwidth.** List responses default to slim representations; detail requires an explicit fetch. `?fields=` sparse fieldsets on the heavy resources.
2. **Clock skew.** Devices have wrong clocks. Always accept `device_recorded_at` but authoritatively stamp `received_at` server-side unless the user has backdating permission. Return server time in every response header so clients can correct.
3. **Force-upgrade.** `GET /app/config` returns `{min_supported_version, latest_version, maintenance: bool, message}` per client. The apps check it on launch. Ship this in v1 or you will regret it the first time you need to kill a buggy build.
4. **Localised strings server-side.** Statuses, reasons, and error `detail` are returned already translated per `Accept-Language`, with a stable machine `code` alongside. Clients switch on `code`, display `detail`.
5. **Money in responses** is always `{amount: <integer minor units>, currency: "USD", formatted: "$5.99"}`. Never a bare number, never a pre-formatted string alone.
6. **Timestamps** are ISO-8601 with offset, always. Also return `timezone` on the tenant so clients render business days correctly.
